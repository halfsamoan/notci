# notci v8 (2026-10-23) — 저배터리 깜빡임

레퍼런스 조사(조사 4갈래 31건 → 디자인 3안 → 심사) 결과, 저배터리를 실제로 깜빡이는 노치 앱 중 소스로 확인한 것은 Atoll(GitHub 별 약 5천)과 DynamicNotch였다. 둘 다 빨간 잔량 표시의 opacity를 0.3↔1.0 사이 ease-in-out으로 오가고, 20%를 내려갈 때 한 번 재생한다. boring.notch와 iOS 상태 막대는 깜빡임 없이 빨강으로만 남는다. 트리거는 안드로이드 PowerUI(20/10 하강, 25 재무장)를 따랐다.

| # | 상태 | 확인 |
|---|---|---|
| 22 | 10% 알약, 깜빡임 중간 | 링(트랙+호)만 opacity 77까지 흐려짐. 아이콘·파형·알약은 그대로 |
| 23 | 10% 알약, 깜빡임 뒤 | 빨간 10% 호 + 25% 트랙으로 정지 |

- 모션: 링 `St.DrawingArea`의 actor opacity 255→77→255를 500 ms씩 4구간(`EASE_IN_OUT_SINE`, 1 Hz, 2.0 s). 링이 채움/레벨 변경 중이면 그게 끝나고 `alertGap` 300 ms 뒤 시작.
- 트리거: 빨강(20% 미만)에 들어갈 때와 10% 이하로 내려갈 때 한 번씩. 20–24%는 재알림 없음, 25% 이상이면 재무장. 연결·셸 재시작 직후 이미 빨강이면 한 번.
- 카드·토스트 링은 깜빡이지 않는다. 카드가 열려 있거나 다른 모듈이 섬을 차지했거나 전체화면·잠금·개요면 기다렸다가 작은 섬이 다시 보일 때 한 번.
- 애니메이션 끔이면 재생하지 않고 빨강만 남긴다. 화면 낭독기 이름에 "배터리 부족"이 붙는다.
- 격리 셸 `ux-tools/probe_lowbattery.js` 14항목 3회 연속 PASS(곡선 255,193,93,93,193,255,193,93,93,194,255).

**v8 추가 변경(같은 날):** 헤드셋 알약·카드의 파형을 뺐다(사용자: Spotify 파형과 둘이 같이 움직여 산만함). 알약은 아이콘 + 링, 폭 52 → 56 스냅. Spotify 파형은 그대로. 실세션 v7에서 링이 안 보인 원인은 `UPowerGlib` `get_devices2()`가 이미 해제된 UpDevice를 돌려줘 매 동기화가 예외로 끊긴 것이었다(journal "has been already finalized"). UPower를 D-Bus로 직접 읽는 비동기 캐시로 바꿨고, 격리 셸에서 실제 UPower의 XM5 100%가 캐시에 잡히는 것을 확인했다.

**v8 CPU 수정(같은 날):** 실제 세션에서 gnome-shell이 코어의 약 25~30%를 쓰고 CPU가 90 °C까지 올랐다. notci만 잠깐 끄면 29% → 17%, Archsport는 켜고 끄든 차이가 없었고(21~22%), matci도 거의 0이었다. 원인은 Spotify 알약 파형의 무한 `PropertyTransition`이었다. 120 Hz 패널에서 매 프레임 셸 전체를 다시 그렸고, v7에서는 헤드셋 파형까지 두 벌이 돌았다. 같은 원인으로 "needs an allocation" 경고도 분당 60~150건 쌓였다. 파형을 약 15 fps 타이머로 바꿨다. 곡선·주기·높이·정지 높이는 그대로다. 격리 셸(60 Hz) 결과는 재생 중 59.7 fps·7.0% → 15.0 fps·3.6%, 정지 0 fps, 재생 중 경고 0건이다. 실기기(120 Hz)는 프레임이 8분의 1이 된다.

# notci v9 / Archsport v31 / matci v29 (2026-10-23) — 최적화

재로그인 뒤 실세션에서 notci가 차지하는 CPU는 코어 약 12%에서 약 2%로 줄었다(켬 11.4%, 끔 9.3%). 이어서 남은 낭비를 정리했다.

| 항목 | 전 | 후 |
|---|---|---|
| 섬 펼침·접힘 경고 (`needs an allocation`) | 한 번에 약 40건, 실세션 로그인 후 4분간 327건 | 0건(격리 셸 전체 프로브 실행 기준). 클릭 영역을 `NotchLayout`이 할당 중 배치 |
| Spotify 앨범 아트 | 정규식이 32자 id를 기대해 축소가 한 번도 안 됨, 항상 640 px(텍스처 1.6 MB) | 실제 24자 id, 항상 300 px(0.36 MB). 분수 배율 1.67에서도 64 논리 px 카드에 충분히 선명 |
| 카카오톡 팝업 창 신호 | 창마다 `shown`·`unmanaged` 연결, 해제 없음(재표시마다 누적) | 창당 한 번 연결, `unmanaged`·destroy에서 해제 |
| EasyEffects | 끌 방법 없음(PSS 219 MB, 재생 중 CPU 3.5%) | 프리셋 줄 끝 "끄기" 칩(24). 프리셋을 누르면 다시 숨김 서비스로 켜짐 |

손대지 않은 것: matci 목록 재생성(카드를 연 동안 5초마다 몇 줄, 건너뛰면 0.01 GB 단위 수치가 멈춤), Wise식 메모리 정리(사용자 결정으로 포기). Archsport worker를 경기 없는 동안 내렸다 다시 띄우는 '낮잠'은 구현했다가 검토에서 되돌렸다: 새 worker가 경기 뒤 4시간 동안 시작 프로브로 API를 더 쓰고, 낮잠 중 벽시계 보정(NTP)을 놓쳐 킥오프 알림이 빠질 수 있고, 할당량 쿨다운 상태가 사라진다. 얻는 것은 16 MB(RAM 0.1%)뿐이다.

검토(10 에이전트)에서 고친 것: 섬 계약 해시에 `NotchLayout` 포함, 카카오 팝업 정리를 이벤트가 아닌 actor로 맞추고 다른 카드가 활성일 때 root를 비우지 않음, 카카오를 끄거나 본문을 끈 뒤에도 팝업을 미러하던 문제, EasyEffects '다른 EasyEffects'·'실패' 표시가 영구히 남아 칩이 죽던 문제(실행 상태가 바뀌면 초기화, 실패는 다시 누를 수 있음, `flatpak ps` 실패는 재시도 가능한 실패로).
